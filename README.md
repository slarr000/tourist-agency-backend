# IS Tour

### Информационная система зарубежного представительства туристической фирмы

Веб-приложение для учёта туристов, поездок, размещения, экскурсий, грузов и финансов. Проект разработан для курсовой работы по **варианту № 10**.

## Возможности

| Раздел | Что можно делать |
|---|---|
| **Туристы** | Вести данные туристов, паспорта, категории и сведения о детях |
| **Операции** | Управлять рейсами, поездками, документами, гостиницами, экскурсиями, путёвками и финансами |
| **Склад** | Учитывать приём и отправку грузов, места, вес, маркировку, упаковку и страховку |
| **Отчёты** | Формировать отчёты по заданию, применять фильтры и экспортировать результаты в CSV |
| **Месячный отчёт** | Просматривать продажи и документы, закрывать завершённый месяц и сохранять версии отчёта |

Доступ к рабочей панели предоставляется сотрудникам после входа. Для связанных записей в формах доступны поиск и выбор по понятным названиям вместо ручного ввода идентификаторов.

## Архитектура

```text
Браузер  →  React + TypeScript  →  ASP.NET Core API  →  PostgreSQL
              интерфейс                backend        процедуры и функции
```

Это репозиторий клиентской части. Серверная часть находится отдельно: [tourist-agency-backend](https://github.com/slarr000/tourist-agency-backend).

Backend обращается к данным и отчётам через процедуры PostgreSQL (`CALL`); SQL-функции содержат переиспользуемую логику. Публичный лендинг доступен без входа, административные разделы и API защищены сессией сотрудника.

**Стек:** React 19 · TypeScript · Vite · Material UI · React Router · ASP.NET Core / .NET 9 · PostgreSQL

## Запуск

### Что понадобится

- Node.js **20.19+** или **22.12+** и npm;
- .NET SDK **9.0**;
- PostgreSQL (рекомендуется версия 16-18) и существующая настроенная база приложения;
- клиентский и серверный проекты. В примерах ниже они расположены рядом:

```text
project/
├── tourist-agency-client/
└── TouristAgencyApp/
    ├── Database/
    ├── appsettings.Development.json
    └── TouristAgencyApp.csproj
```

> **Важно:** Проект является кроссплатформенным (Linux/Windows/macOS), но требует правильной настройки локального окружения. Не копируйте папки `bin`, `obj` и `node_modules` при переносе проекта между разными операционными системами.

### 1. Подготовьте базу

Создайте пустую базу данных (например, `Touristic Firma`) в pgAdmin или консоли PostgreSQL. 

Для развертывания готовой схемы со всеми таблицами, хранимыми процедурами и тестовыми данными восстановите актуальный SQL-дамп (например, `BD_backup.sql`). Пример восстановления через терминал Windows (`cmd`):

```cmd
"C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d "Touristic Firma" -f "C:\Путь\К\Файлу\BD_backup.sql"
```
*(Путь к `psql.exe` может отличаться в зависимости от установленной версии).*

Создайте отдельную учётную запись сотрудника с помощью процедуры `app_create_employee_account_proc`, передав ей индивидуальные логин и пароль. В текущей реализации **для новой учётной записи допускается пароль от 1 до 6 символов**. 

### 2. Запустите backend

В каталоге серверного проекта настройте подключение к PostgreSQL. Откройте файл `appsettings.Development.json` (или используйте .NET User Secrets) и обновите строку подключения `DefaultConnection`, указав адрес сервера, порт, точное имя базы данных и ваш пароль суперпользователя:

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=localhost;Port=5432;Database=Touristic Firma;Username=postgres;Password=ВашПароль"
}
```

Затем откройте терминал в папке серверного проекта и выполните запуск:

```bash
dotnet restore
dotnet run --launch-profile https
```

Профиль `https` запускает API на **https://localhost:7062**. При первом запуске (особенно на Windows) установите доверие к локальному сертификату разработчика, чтобы избежать проблем с CORS на фронтенде:

```bash
dotnet dev-certs https --trust
```

### 3. Запустите frontend

В другом терминале из каталога клиентского проекта установите зависимости и запустите сервер разработчика:

```bash
npm install
test -f .env || cp .env.example .env
npm run dev -- --host localhost --port 5173 --strictPort
```

> **Решение проблем на Windows:** Если при выполнении команды `npm -v` или `npm install` в PowerShell вы получаете ошибку `PSSecurityException` (выполнение сценариев отключено), разрешите локальные скрипты разработчика следующей командой:
> 
```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> 
```

При необходимости измените в `.env` значение `VITE_API_BASE_URL`: по умолчанию используется `https://localhost:7062`. 

Откройте **http://localhost:5173** и войдите через кнопку на лендинге или страницу `http://localhost:5173/admin/login`. Оставьте оба сервера работающими; для остановки нажмите **Ctrl+C** в соответствующих терминалах.

## Сценарий демонстрации

1. **Туристы.** Откройте карточку туриста и покажите персональные и паспортные данные.
2. **Операции.** Покажите рейс, поездку, бронирование гостиницы и журнал оформления документов. При наличии ребёнка отдельно покажите отметки участия в поездке и проживания.
3. **Экскурсии.** Покажите запись взрослого, затем ребёнка с сопровождающим; сформируйте список участников для агентства.
4. **Склад.** Откройте грузовую ведомость: дата приёма, маркировка, вес, статус и фактическая дата отправки.
5. **Отчёты.** Сформируйте таможенный список, списки расселения, отчёт о грузообороте или финансовый отчёт. При необходимости выгрузите результат в CSV.
6. **Месячный отчёт.** Покажите итог, продажи и документы. Завершённый месяц можно закрыть после ручного подтверждения каталога; исправление создаёт новую версию с причиной.

Если загружен набор `ResetAndSeedDefenseDemo.sql`, для демонстрации можно выбрать период **15.10.2026–30.11.2026**, рейсы `DEF-401` и `DEF-512`, а также ежемесячные отчёты за октябрь или ноябрь 2026 года. Набор включает 322 вымышленных взрослых туриста, 66 детей с отметками участия и проживания и дополнительные рейсы `EDU-*`. Результаты зависят от текущего состояния базы. Учебные цены приведены в рублях и не являются коммерческим предложением.

## SQL-скрипты

Скрипты находятся в каталоге `Database/` **серверного проекта**. Следующая таблица предназначена для применения патчей к существующей базе; она не заменяет исходную схему.

| Скрипт | Назначение и порядок |
|---|---|
| `StoredProcedures.sql`, `CourseworkEnhancements.sql` | Базовые процедуры и функции приложения; сначала первый, затем второй |
| `LinkBookingsToVisits.sql` | Связывание бронирований с поездками; после базовых скриптов и загрузки данных |
| `ChildParticipation.sql` | Отдельный учёт детей в поездках и гостиницах; после связи бронирований |
| `CustomsAndTouristCount.sql` | Общий таможенный список и подсчёт туристов с детьми; после учёта участия детей |
| `CargoReceivedDate.sql` | Дата приёма груза и отчёт о грузообороте |
| `CargoAndFlightReports.sql` | Отчёты по видам груза и конкретному рейсу; после `CargoReceivedDate.sql` и `ChildParticipation.sql` |
| `CargoShipmentDate.sql` | Дата фактической отправки и обновлённый отчёт о грузообороте; после `CargoAndFlightReports.sql` |
| `DocumentEvents.sql` | Журнал оформления документов |
| `TourPackageSales.sql` | Фактическая цена продаж путёвок; после `DocumentEvents.sql` |
| `MonthlyBusinessDetails.sql` | Расшифровка месячного отчёта; после `TourPackageSales.sql` |
| `MonthlyReportClosing.sql` | Закрытие месяца и версии отчёта; после `MonthlyBusinessDetails.sql` |
| `FixCategoryRatio.sql` | Соотношение категорий туристов |
| `ExcursionParticipants.sql` | Список участников экскурсий для агентства |
| `FinancialReportDetails.sql` | Детализация финансовых отчётов; после `CourseworkEnhancements.sql` |

> Некоторые старые скрипты повторно определяют функции отчётов. При переустановке соблюдайте порядок и повторно применяйте последующие специализированные скрипты. После изменения процедур перезапустите backend.

### Демонстрационные данные

`DemoData.sql`, `DemoDataSupplement.sql` и `CourseworkSampleData.sql` добавляют синтетические записи; перед запуском изучите условия внутри файлов. Скрипт `UpdateDefenseDemoPrices.sql` предназначен только для исходного демонстрационного денежного набора и отклоняет изменения, если записи уже отличаются.

> **Удаление данных:** `ResetAndSeedDefenseDemo.sql` удаляет все строки бизнес-таблиц схемы `public`, включая закрытые версии отчётов, и загружает новый набор. Учётные записи сотрудников сохраняются. Выполняйте его только в предназначенной для демонстрации базе **после резервного копирования**. Скрипт использует транзакцию и проверяет имя базы `Touristic Firma`.

Для вымышленных грузов в этом наборе предусмотрены дата приёма и примеры отправок, включая отдельный грузовой рейс `EDU-CARGO-01`. Для новых грузов регулярных учебных рейсов статус «Отправлен» задаётся только для рейсов не позднее даты запуска скрипта. Даты не подставляются в уже существующие записи.

## Особенности и ограничения

### Дети и документы

- Сначала создайте поездку сопровождающего, затем отметьте ребёнка в разделе **«Операции → Дети в поездках»**. Проживание отмечается отдельно в **«Проживание детей»** для бронирования этой поездки. Старые отметки автоматически не создаются.
- Для записи ребёнка на экскурсию сначала запишите взрослого на ту же экскурсию. Список для агентства отражает **записи**, а не подтверждённое посещение.
- В таможенном списке ребёнок отображается только при отметке участия; выводится свидетельство о рождении. Отдельные загранпаспорт и виза ребёнка не моделируются.
- Журнал оформления документов заполняется отдельно. Его запись не меняет автоматически признак наличия визы туриста; исторические оформления не добавляются сами.
- В отчёте № 1 человек учитывается один раз на конкретном рейсе и может встретиться на разных рейсах; взрослые без рейса исключаются. Отчёт № 3 считает уникальных взрослых и отмеченных детей за период по дате прибытия. Категория ребёнка определяется по **текущей** категории сопровождающего.

### Грузы и рейсы

- Дата отправки указывается вручную и не может быть раньше даты приёма. Старые грузы со статусом «Отправлен» и неизвестной датой можно редактировать, но они не считаются подтверждёнными отправками.
- Отчёт № 9 отбирает грузы по дате приёма, а рейсы считает только по грузам с подтверждённой датой отправки, в том числе за пределами периода приёма. Записи без даты приёма исключаются.
- Отчёт № 12 отбирает отправленные грузы по фактической дате отправки; доля рассчитывается по фактическому весу. В отчёте № 15 показываются грузы взрослых пассажиров, назначенные выбранному рейсу, независимо от статуса.
- Назначение рейса и отметка отправки груза сами по себе не подтверждают фактический вылет самолёта.

### Финансы и месячный отчёт

- Фактическая цена продажи фиксируется отдельно от текущей цены каталога. Если у старой продажи нет цены, выручка от путёвок за месяц считается неизвестной. Продажа **не создаёт** финансовую операцию автоматически: доход регистрируется отдельно.
- Финансовые операции отбираются по дате и указанному рейсу. При выборе категории общие операции распределяются по взрослым с учётом поездок и текущих назначений; дети не участвуют. Историческая категория не хранится. Нераспределённые суммы показываются отдельно; округление до копеек может дать небольшое расхождение.
- В финансовом отчёте количество операций по статье показывает, сколько операций целиком или частично отнесено к категории: общая операция может учитываться для обеих категорий. CSV отчёта по статьям содержит отдельный блок нераспределённых сумм.
- Рентабельность рассчитывается как `(доход − расход) / расход × 100%`; при нулевом расходе она не определяется. При нераспределённых операциях показатели категории неполные.
- До закрытия месяца данные о востребованности и доступности путёвок помечаются как неизвестные. Для закрытия завершённого месяца вручную подтвердите все предлагавшиеся путёвки и количество мест, в том числе снятые с продажи; удалённые путёвки выбрать нельзя. Если подтвердить данные невозможно, оставьте месяц незакрытым.
- Закрытая версия сохраняет итог, расшифровку и подтверждённый каталог. Поздние изменения исходных записей не меняют её; для исправления создаётся новая версия с причиной. Закрытие не блокирует изменение исходных данных и не является юридическим архивом. CSV месячного отчёта содержит только итоговую строку.
- Отчёт № 14 за период считает каждого взрослого с прибытием один раз; режим «За всё время» включает всех зарегистрированных взрослых. Дети в соотношение категорий не входят.
