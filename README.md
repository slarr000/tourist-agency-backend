# IS Tour (Backend)

### Информационная система зарубежного представительства туристической фирмы

Веб-приложение для учёта туристов, поездок, размещения, экскурсий, грузов и финансов. Проект разработан для курсовой работы по **варианту № 10**.

## Возможности

| Раздел | Что можно делать |
|---|---|
| **Туристы** | Вести данные туристов, паспорта, категории и сведения о детях |
| **Операции** | Управлять рейсами, поездками, документами, гостиницами, экскурсиями, путёвками и финансами |
| **Склад** | Учитывать приём и отправку грузов, места, вес, маркировку, упаковку и страховку |
| **Отчёты** | Формировать отчёты по заданию, применять фильтры и экспортировать результаты в CSV |
| **Месячный отчёт** | Просматривать продажи и документы, закрывать завершённый месяц и сохранять версии отчёта |

## Архитектура

```text
Браузер  →  React + TypeScript  →  ASP.NET Core API  →  PostgreSQL
              интерфейс                backend        процедуры и функции
```

Это репозиторий **серверной части (API)** и базы данных. Клиентская часть (фронтенд) находится отдельно в репозитории: [tourist-agency-client](https://github.com/slarr000/tourist-agency-client).

Backend обращается к данным и отчётам через процедуры PostgreSQL (`CALL`); SQL-функции содержат переиспользуемую логику. Публичный лендинг доступен без входа, административные разделы и API защищены сессией сотрудника.

**Стек:** ASP.NET Core / .NET 9 · C# · PostgreSQL

## Запуск

### Что понадобится

- .NET SDK **9.0**;
- PostgreSQL (рекомендуется версия 16-18) и pgAdmin 4;
- Node.js (для запуска смежного клиентского приложения);
- Интегрированная среда разработки (JetBrains Rider или Visual Studio 2022+).

> **Важно:** Проект является кроссплатформенным (Linux/Windows/macOS), но требует правильной настройки локального окружения. При переносе репозитория между разными ОС не копируйте папки `bin` и `obj`.

### 1. Подготовьте базу данных

Создайте пустую базу данных (например, `Touristic Firma`) в pgAdmin. 

Для развертывания готовой схемы со всеми таблицами, хранимыми процедурами и тестовыми данными восстановите актуальный SQL-дамп (например, `BD_backup.sql`). Пример восстановления через командную строку Windows (`cmd`):

```cmd
"C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d "Touristic Firma" -f "C:\Путь\К\Файлу\BD_backup.sql"
```

Создайте учётную запись сотрудника с помощью процедуры `app_create_employee_account_proc`, передав ей индивидуальные логин и пароль (допускается пароль от 1 до 6 символов для учебных целей).

### 2. Запустите backend

В корне серверного проекта откройте файл `appsettings.Development.json` (или используйте .NET User Secrets) и обновите строку подключения `DefaultConnection`, указав актуальный пароль от вашей локальной БД:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=Touristic Firma;Username=postgres;Password=ВашПароль"
  }
}
```

Откройте терминал в папке проекта и выполните команды:

```bash
dotnet restore
dotnet run --launch-profile https
```

Профиль `https` запускает API на **https://localhost:7062**. При первом запуске на Windows обязательно установите доверие к локальному сертификату разработчика для корректной работы CORS:

```bash
dotnet dev-certs https --trust
```

## Частые проблемы при переносе на Windows

Если вы перенесли файлы проекта с Linux (ext4) на Windows (NTFS), например, через USB-накопитель, вы можете столкнуться со следующими проблемами:

**1. Ошибка "invalid object" или "Error building trees" при коммите в Git**
При копировании файлов индекс репозитория может повредиться. Для безопасного восстановления кэша Git выполните в PowerShell:
```powershell
Remove-Item .\.git\index -Force
git add .
```

**2. Ошибка "PSSecurityException" при запуске npm (для фронтенда)**
По умолчанию Windows блокирует выполнение локальных скриптов разработчика. Выполните в PowerShell:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## SQL-скрипты

Скрипты находятся в каталоге `Database/` данного проекта. Следующая таблица предназначена для применения патчей к существующей базе. 

| Скрипт | Назначение |
|---|---|
| `StoredProcedures.sql` | Базовые процедуры и функции приложения |
| `LinkBookingsToVisits.sql` | Связывание бронирований с поездками |
| `ChildParticipation.sql` | Отдельный учёт детей в поездках и гостиницах |
| `MonthlyReportClosing.sql` | Закрытие месяца и версии отчёта |
| `FinancialReportDetails.sql` | Детализация финансовых отчётов |

*(Полный список и порядок применения скриптов см. в исходном репозитории).*

> **Демонстрационные данные:** Скрипт `ResetAndSeedDefenseDemo.sql` удаляет все строки бизнес-таблиц схемы `public` и загружает новый набор для демонстрации курсовой. Выполняйте его только в тестовой базе **после резервного копирования**.
